# Sisyphus — 에이전트 작업 방식 이해하기

이 문서는 에이전트가 무엇을 대답하는지보다, 왜 에이전트 방식이 필요한지와 어떤 종류의 일을 맡길 때 도움을 주는지 설명하는 데 목적이 있다.

## 한 줄 요약

**Sisyphus는 한 번의 답변보다 여러 단계가 필요한 조사, 정리, 비교, 수정 작업을 더 체계적으로 맡기기 위한 에이전트 방식이다.**

## 이 폴더에서 다루는 방향

- 에이전트 내부 구조보다 사용 목적 설명
- 기능 나열보다 어떤 일을 맡기면 좋은지 설명
- 초급 사용자가 "질문"과 "작업 위임"의 차이를 이해하게 하는 데 초점

## 먼저 다루면 좋은 것

- [ ] 일반 채팅과 에이전트 작업의 차이
- [ ] 왜 긴 작업에는 에이전트가 유리한지
- [ ] 조사, 비교, 정리 같은 일에 강한 이유
- [ ] 결과를 바로 믿지 않고 검토해야 하는 이유
- [ ] OpenCode 안에서 에이전트를 부르는 흐름

## 이 문서에서 특히 다루고 싶은 것

- [ ] `/agent` 같은 명령이 어떤 역할을 하는지
- [ ] 서브에이전트를 쓰는 이유
- [ ] 여러 단계 작업을 한 번에 맡기는 감각
- [ ] 논문 작업에서 자료 조사와 구조 점검에 왜 유용한지
