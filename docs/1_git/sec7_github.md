# GitHub 연동

> 중요도: ⭐⭐⭐

Git을 로컬에서만 써도 도움이 되지만, GitHub까지 연결하면 훨씬 안심하고 쓸 수 있다. 여기서는 아주 실용적으로만 본다.

## 한 줄 요약

**GitHub는 Git 기록을 온라인에 백업하고 다른 곳과 연결하는 저장소다.**

## 어떻게 생각하면 되나?

내 컴퓨터 안의 Git 저장소만 있으면 로컬 기록은 남는다.

여기에 GitHub를 연결하면, 그 기록을 인터넷에도 하나 더 올려두는 셈이다.

그래서 컴퓨터가 바뀌거나 문제가 생겨도 이어서 작업하기 쉬워진다.

## 그냥 이렇게 쓰면 된다

처음 연결할 때는 아래 순서로 보면 된다.

1. GitHub 계정을 만든다
2. 새 저장소를 만든다
3. SSH 키를 만든다
4. 공개 키를 GitHub에 등록한다
5. 로컬 프로젝트를 연결하고 `push`한다

직접 할 경우 보통 이렇게 연결한다.

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
git remote add origin git@github.com:내아이디/masters-thesis.git
git push -u origin main
```

실제로는 에이전트에게 이렇게 맡겨도 된다.

- "GitHub 저장소 연결해줘"
- "SSH 키 방식으로 GitHub 설정 도와줘"
- "이 프로젝트를 GitHub에 연결하고 push까지 해줘"

## 이것만 기억하면 된다

1. GitHub는 온라인 백업이다
2. 프로젝트마다 한 번 연결해두면 된다
3. 연결 뒤에는 커밋 후 `push`하면 된다
4. 처음 설정은 에이전트와 함께 해도 충분하다

## 고급 과정

GitHub를 더 정확히 이해하면, Git 자체와 GitHub 서비스가 서로 다른 것이라는 점이 보인다.

### 1. Git과 GitHub는 무엇이 다른가?

Git은 내 컴퓨터에서 버전 기록을 관리하는 도구다.

GitHub는 그 Git 저장소를 원격으로 올려두고 공유하는 서비스다.

즉:

- Git: 버전 관리 도구
- GitHub: Git 저장소를 올려두는 원격 서비스

그래서 인터넷이 없어도 로컬 Git 커밋은 가능하지만, GitHub와 동기화하려면 네트워크가 필요하다.

### 2. `remote`는 무엇인가?

Git에서 `origin` 같은 이름은 원격 저장소를 가리키는 별칭이다.

```bash
git remote add origin git@github.com:내아이디/masters-thesis.git
```

이 명령은 내 로컬 저장소가 앞으로 어느 GitHub 저장소와 연결될지 알려주는 작업이다.

### 3. 왜 SSH 키를 쓰나?

SSH 키는 비밀번호를 매번 입력하지 않고도 안전하게 인증하기 위한 방식이다.

보통은:

- 내 컴퓨터에 개인 키를 두고
- GitHub에는 공개 키를 등록한다

이렇게 해서 GitHub가 "이 컴퓨터는 허용된 사용자다"라고 확인할 수 있게 한다.

### 4. `push -u`는 왜 하나?

```bash
git push -u origin main
```

여기서 `-u`는 현재 로컬 브랜치와 원격 브랜치를 연결해두는 역할을 한다.

한 번 연결해두면 이후에는 더 짧게 `git push`, `git pull`만 써도 되는 경우가 많다.

### 5. GitHub를 연결하면 무엇이 좋아지나?

단순 백업 외에도 다음 이점이 생긴다.

- 다른 컴퓨터에서 `clone`해서 이어서 작업 가능
- 협업 시 변경 공유가 쉬움
- Pull Request 같은 검토 흐름 사용 가능
- 로컬 문제 발생 시 복구 기준점이 생김
