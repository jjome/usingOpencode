# 되돌리기

> 중요도: ⭐⭐ — 실수했을 때 구원해주는 안전망. 자주 쓰진 않지만 알아두면 든든하다.

## 상황별 되돌리기

### 1. 아직 커밋 안 한 변경을 취소하고 싶다

파일을 수정했는데 마음에 안 들어서 마지막 커밋 상태로 되돌리고 싶을 때.

```bash
# 특정 파일을 마지막 커밋 상태로
git checkout -- 서론.md

# 모든 변경을 마지막 커밋 상태로
git checkout -- .
```

**주의**: 이 명령은 수정 내용을 완전히 버린다. 되돌릴 수 없다.

### 2. 특정 커밋 시점으로 파일을 보고 싶다

"지난주에 서론이 어땠지?" 확인하고 싶을 때.

```bash
# 이력 확인
git log --oneline
# a1b2c3d 참고문헌 정리
# f4e5d6c 2장 피드백 반영
# 7g8h9i0 서론 초안 작성

# 특정 커밋 시점의 파일 내용 보기
git show 7g8h9i0:서론.md
```

현재 파일은 건드리지 않고 과거 버전만 확인할 수 있다.

### 3. 특정 커밋을 취소하고 싶다

"아까 그 수정 전체를 없던 일로 하고 싶다."

```bash
git revert a1b2c3d
```

`revert`는 해당 커밋의 변경을 **반대로** 적용하는 새 커밋을 만든다. 이력이 남아서 안전하다.

```
[커밋 5] Revert "참고문헌 정리"    ← 커밋 4를 되돌리는 새 커밋
[커밋 4] 참고문헌 정리              ← 이 커밋의 변경이 취소됨
[커밋 3] 2장 피드백 반영
```

## 핵심 요약

| 상황 | 명령어 | 이력 |
|---|---|---|
| 수정했는데 커밋 전, 되돌리고 싶다 | `git checkout -- 파일명` | 이력 없음 (수정 사라짐) |
| 과거 커밋의 파일을 보고 싶다 | `git show 해시:파일명` | 현재 파일 변경 없음 |
| 특정 커밋을 취소하고 싶다 | `git revert 해시` | 취소 이력이 새 커밋으로 남음 |

## 긴급 상황

뭔가 크게 잘못됐을 때, 당황하지 말고:

1. `git status`로 현재 상태 확인
2. `git log --oneline`로 이력 확인
3. AI에게 상황을 설명하고 도움 요청 ("git에서 이런 상태인데 어떻게 돌아가나요?")

Git은 커밋한 내용을 거의 잃어버리지 않는다. 침착하게 대응하면 된다.
