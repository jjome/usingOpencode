# 되돌리기

> 중요도: ⭐⭐

Git의 큰 장점 중 하나는 되돌리기다. 하지만 처음에는 직접 해결하려고 무리하지 말고, 아주 안전한 감각부터 잡는 편이 좋다.

## 한 줄 요약

**Git은 잘못된 변경을 되돌릴 수 있게 도와주는 도구다.**

## 어떻게 생각하면 되나?

작업하다 보면 틀린 수정, 과한 수정, 원하지 않는 저장이 생길 수 있다.

Git은 이런 상황에서 "완전히 망했다"가 아니라 "어느 시점으로 어떻게 돌아갈지 고르면 된다"는 식으로 생각하게 해준다.

## 그냥 이렇게 쓰면 된다

처음에는 혼자 명령어를 고르기보다, 상태를 보고 안전하게 되돌리는 쪽이 좋다.

에이전트에게 이렇게 말하면 된다.

- "방금 한 변경을 되돌리고 싶어"
- "이 파일만 이전 상태로 돌리고 싶어"
- "최근 커밋을 취소하고 싶어"
- "지금 상태를 보고 가장 안전한 되돌리기 방법을 알려줘"

직접 할 때도 가장 먼저 할 일은 상태 확인이다.

```bash
git status
```

## 이것만 기억하면 된다

1. Git에서는 되돌릴 수 있는 경우가 많다
2. 먼저 현재 상태를 확인하는 것이 중요하다
3. 무리해서 한 번에 해결하려 하지 않는 편이 안전하다
4. 헷갈리면 에이전트에게 맡기면 된다

## 고급 과정

되돌리기에서 가장 중요한 것은 "무엇을 되돌리고 싶은지"를 구분하는 것이다. Git은 같은 되돌리기처럼 보여도 대상 상태에 따라 명령이 달라진다.

### 1. 무엇을 되돌리는가?

보통 되돌리기는 세 층 중 하나를 대상으로 한다.

- 작업 폴더의 수정
- staging에 올린 변경
- 이미 만든 commit

이 셋을 구분하지 않으면 명령어가 헷갈린다.

### 2. 왜 `status`가 먼저인가?

`git status`를 보면 지금 변경이 어디에 있는지 판단할 수 있다.

- 아직 파일만 수정했는지
- 이미 staging에 올렸는지
- commit까지 했는지

즉, 상태를 알아야 안전한 되돌리기 방법도 고를 수 있다.

### 3. 대표적인 되돌리기 방향

처음에는 명령어를 외우기보다 종류만 구분해도 도움이 된다.

- 작업 파일을 되돌리기
- staging만 풀기
- 커밋을 취소하되 기록은 남기기
- 특정 커밋을 반대로 적용해 되돌리기

여기서 중요한 점은, 되돌리기에도 "기록을 남기며 되돌리는 방식"과 "현재 상태를 다시 맞추는 방식"이 있다는 것이다.

### 4. 왜 위험한 명령이 있나?

Git에는 일부 되돌리기 명령처럼 보이지만 실제로는 내용을 강하게 바꾸는 명령도 있다.

예를 들어 이미 확인하지 않은 변경을 버려버리거나, 커밋 구조를 바꿔버리는 경우가 있다.

그래서 초급 단계에서는:

- 현재 상태를 먼저 확인하고
- 정말 버려도 되는 변경인지 판단하고
- 필요하면 에이전트에게 안전한 방법을 고르게 하는 편이 좋다

### 5. 커밋을 했어도 끝이 아닌 이유

커밋을 했다고 해서 영원히 못 바꾸는 것은 아니다.

Git은 커밋 이후에도:

- 이전 커밋을 비교할 수 있고
- 새로운 커밋으로 되돌림을 기록할 수 있고
- 특정 시점으로 돌아갈 수 있다

그래서 Git의 되돌리기는 "실수하면 끝"이 아니라 "기록을 보며 복구할 수 있음"에 가깝다.
