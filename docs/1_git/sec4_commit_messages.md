# 커밋 메시지 잘 쓰는 법

> 중요도: ⭐⭐ — AI 에이전트가 대신 써주지만, 원리를 알면 이력을 더 잘 읽을 수 있다.

## 왜 신경 써야 하나

커밋 메시지는 미래의 나를 위한 메모다. 3개월 뒤에 `git log`를 봤을 때:

```
# 나쁜 예 — 아무 정보가 없다
a1b2c3d 수정
f4e5d6c 업데이트
7g8h9i0 작업

# 좋은 예 — 논문 진행 상황이 보인다
a1b2c3d 3장 실험 결과 표 추가
f4e5d6c 서론에 연구 배경 보충
7g8h9i0 참고문헌 APA 형식으로 통일
```

## 논문 맥락에서의 메시지 패턴

### 구조: **무엇을 + 어떻게**

```
서론 초안 작성
2장에 선행연구 비교표 추가
지도교수 피드백 반영 (서론 논증 구조 변경)
참고문헌 APA 7th 형식으로 수정
영문 초록 추가
```

### 피해야 할 것

| 나쁜 메시지 | 이유 |
|---|---|
| `수정` | 뭘 수정했는지 모른다 |
| `업데이트` | 모든 커밋이 업데이트다 |
| `작업 중` | 나중에 봐도 정보가 없다 |
| `ㅇㅇ` | ... |

## AI 에이전트와의 협업

OpenCode의 git-master 에이전트는 변경 내용을 분석해서 커밋 메시지를 자동 생성한다. 직접 쓸 필요가 없는 경우가 많다.

하지만 메시지의 원리를 알아야:
- 에이전트가 만든 메시지가 적절한지 판단할 수 있다
- `git log`를 읽고 이력을 이해할 수 있다
- 필요할 때 직접 수정할 수 있다
