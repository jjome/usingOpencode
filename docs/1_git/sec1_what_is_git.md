# Git이란 무엇인가

> 중요도: ⭐⭐⭐

프로그래머가 아니어도 Git을 이해할 수 있다. 핵심만 짚는다.

## 한 줄 요약

**Git은 파일의 변경 이력을 기록하는 도구다.**

## "최종_진짜최종" 문제

논문을 쓰다 보면 이런 파일이 생긴다:

```
논문_초안.docx
논문_수정.docx
논문_최종.docx
논문_최종_수정.docx
논문_진짜최종.docx
논문_진짜최종_v2.docx
논문_제출용_final.docx
```

어느 게 진짜 최종인지 모른다. 뭘 고쳤는지도 모른다. 지도교수 피드백 반영 전으로 돌아가고 싶은데 방법이 없다.

**Git은 이 문제를 해결한다.**

## Git의 핵심 개념

### 1. 저장소 (Repository)

논문 폴더 자체가 저장소가 된다. Git이 이 폴더 안의 모든 변경을 추적한다.

```
내_논문/          ← 이 폴더가 저장소
├── 서론.md
├── 본론.md
├── 결론.md
└── 참고문헌.md
```

### 2. 커밋 (Commit)

"지금 이 상태를 저장해둔다"는 뜻이다. 게임의 세이브 포인트와 같다.

```
[커밋 1] 서론 초안 작성         ← 여기로 되돌아갈 수 있다
[커밋 2] 서론 피드백 반영       ← 여기로도
[커밋 3] 본론 1장 추가          ← 여기로도
[커밋 4] 참고문헌 정리          ← 현재 상태
```

각 커밋에는 **언제, 무엇을 바꿨는지** 메시지가 붙는다. 나중에 이력을 보면 논문이 어떻게 발전했는지 한눈에 보인다.

### 3. 원격 저장소 (Remote)

내 컴퓨터에만 있으면 컴퓨터가 고장나면 끝이다. GitHub 같은 곳에 올려두면:

- **백업**: 컴퓨터가 망가져도 안전하다
- **공유**: 지도교수에게 링크 하나로 공유할 수 있다
- **어디서든**: 다른 컴퓨터에서도 이어서 작업할 수 있다

## Git vs Google Docs

| | Git | Google Docs |
|---|---|---|
| 변경 이력 | 내가 원하는 시점에 저장 (커밋) | 자동 저장 (타이핑할 때마다) |
| 이력 단위 | "서론 완성" 같은 의미 있는 단위 | 글자 단위 |
| 되돌리기 | 특정 커밋으로 정확히 복원 | 타임라인에서 대략적으로 찾기 |
| 오프라인 | 완전 가능 | 불가능 |
| 파일 형식 | 텍스트 기반 (Markdown) 최적 | 자체 형식 |

Git은 "의미 있는 단위"로 이력을 남기기 때문에, 나중에 "서론을 고치기 전으로 돌아가자"가 가능하다.

## 이 가이드에서 쓰는 방식

이 스터디에서는 논문을 **Markdown**(.md)으로 작성한다.

- Markdown은 텍스트 파일이라 Git과 궁합이 매우 좋다
- `.docx`는 바이너리 파일이라 Git이 변경 내용을 제대로 추적하지 못한다
- Cursor 편집기에서 Markdown을 쓰면 AI 도움도 바로 받을 수 있다

## 핵심 정리

| 개념 | 비유 | 설명 |
|---|---|---|
| 저장소 | 논문 폴더 | Git이 추적하는 폴더 |
| 커밋 | 세이브 포인트 | 특정 시점의 상태를 저장 |
| 원격 저장소 | 클라우드 백업 | GitHub에 올려둔 사본 |
| 이력 | 논문 일지 | 언제 뭘 고쳤는지 기록 |
