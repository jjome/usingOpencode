# 브랜치 기초

> 중요도: ⭐⭐ — 처음부터 꼭 쓸 필요는 없지만, 큰 수정을 할 때 있으면 편하다.

## 브랜치란?

아주 간단히 말하면, **원본을 잠깐 옆에 두고 다른 버전에서 작업하는 것**이다.

즉, 지금 쓰고 있는 논문을 바로 건드리지 않고, 복사본 같은 작업 공간에서 먼저 수정해보는 느낌이라고 생각하면 된다.

## 언제 필요하나?

이런 때 있으면 좋다.

- 지도교수 피드백을 한 번에 크게 반영할 때
- 새로운 구조를 시험해보고 싶을 때
- 영어 버전이나 다른 버전을 따로 만들어 보고 싶을 때

핵심은 **큰 수정이 들어갈 때 원본을 잠깐 안전하게 두는 것**이다.

## 처음에는 꼭 안 써도 된다

처음에는 브랜치 없이 하나의 흐름으로 작업해도 충분하다.

브랜치는 "이제 수정 규모가 커져서 따로 작업하는 게 낫겠다" 싶을 때 도입하면 된다.

## 에이전트와 함께 쓸 때

실제로는 직접 명령어를 다루기보다 이렇게 맡기면 된다.

- "이번 피드백 반영은 브랜치 따서 작업해줘"
- "main은 그대로 두고 새 브랜치에서 수정해줘"
- "작업 끝나면 브랜치 정리까지 해줘"
- "지금 이 작업은 브랜치를 쓰는 게 좋은지 판단해줘"

사용자는 브랜치 명령어를 외우기보다, **원본과 별도 작업 공간을 나눌 수 있다**는 느낌만 알면 충분하다.

## 이것만 기억하면 된다

- 브랜치는 다른 작업 줄기 하나를 만드는 것이다
- 큰 수정이 있을 때 유용하다
- 처음에는 안 써도 된다
- 실제 작업은 에이전트에게 맡기면 된다

## 필요할 때 찾아보는 내용

### 자주 쓰는 예시 이름

- `feedback-round1`
- `method-revision`
- `english-version`

```bash
git checkout -b feedback-round1
git checkout main
git merge feedback-round1
```

지금은 명령어를 외우기보다, 필요할 때 다시 찾아보는 정도면 충분하다.
