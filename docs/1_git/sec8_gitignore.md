# .gitignore

> 중요도: ⭐

`.gitignore`는 처음 보면 사소해 보이지만, 프로젝트를 깔끔하게 유지하는 데 도움이 된다. 여기서는 필요한 만큼만 아주 가볍게 본다.

## 한 줄 요약

**`.gitignore`는 Git이 굳이 추적하지 않아도 되는 파일을 빼두는 목록이다.**

## 어떻게 생각하면 되나?

논문 원고나 실제 소스 파일은 기록하고 싶지만, 자동 생성 파일이나 임시 파일까지 모두 Git이 기억하게 만들 필요는 없다.

`.gitignore`는 "이런 파일은 버전 관리에서 빼도 된다"고 알려주는 목록이라고 생각하면 된다.

## 그냥 이렇게 쓰면 된다

보통 프로젝트 초반에 한 번 만들어두면 된다.

예를 들면 이런 파일을 넣는다.

- 자동 생성 파일
- 임시 파일
- 에디터 설정 파일
- 빌드 결과물

논문 프로젝트에서는 예를 들어 이렇게 둘 수 있다.

```gitignore
# OS 자동 생성 파일
.DS_Store
Thumbs.db

# 편집기 설정
.vscode/
.idea/

# 빌드 결과물
*.pdf
output/

# 임시 파일
*.tmp
*.bak
*~

# OpenCode 작업 파일
.opencode/
```

실제로는 에이전트에게 이렇게 맡겨도 된다.

- "논문 프로젝트용 `.gitignore` 만들어줘"
- "지금 폴더에서 Git이 추적하지 않아도 되는 파일 정리해줘"

## 이것만 기억하면 된다

1. `.gitignore`는 불필요한 파일을 빼두는 목록이다
2. 보통 프로젝트 시작할 때 한 번 만든다
3. 원고 자체가 아닌 파일을 깔끔하게 제외하는 데 유용하다
4. 내용이 헷갈리면 에이전트에게 맡겨도 된다

## 고급 과정

`.gitignore`를 더 정확히 이해하면, Git이 무엇을 추적하고 무엇을 무시하는지 구조가 보인다.

### 1. `.gitignore`는 언제 작동하나?

`.gitignore`는 아직 Git이 추적하지 않는 파일에 대해 "앞으로는 무시해라"라고 알려주는 데 가장 잘 작동한다.

즉, 이미 Git이 추적 중인 파일은 `.gitignore`에 적어도 바로 사라지지 않는다.

### 2. 왜 이미 추적 중인 파일은 안 사라지나?

Git은 `.gitignore`를 "처음부터 추적하지 말 파일 목록"에 가깝게 본다.

그래서 한 번 커밋에 들어간 파일은 별도 조치 없이 계속 추적 대상일 수 있다.

이 점 때문에 초반에 `.gitignore`를 잡아두면 더 깔끔하다.

### 3. 어떤 파일을 넣는 게 좋은가?

보통은 다음 기준으로 판단하면 된다.

- 다시 만들어질 수 있는 파일
- 개인 환경에만 필요한 파일
- 작업 결과물이지 원본이 아닌 파일
- 다른 사람과 공유할 필요가 없는 파일

### 4. 너무 많이 빼면 안 되는 이유

`.gitignore`는 편리하지만, 필요한 원본 파일까지 제외하면 오히려 문제가 된다.

예를 들어 실제로 관리해야 할 PDF, 설정 파일, 데이터 파일을 무심코 빼면 협업이나 복구에 어려움이 생길 수 있다.

### 5. 패턴은 어떻게 읽나?

- `*.pdf`: 확장자가 `.pdf`인 파일 전부
- `.vscode/`: `.vscode` 폴더 전체
- `output/`: `output` 디렉터리 아래 내용

즉, `.gitignore`는 파일 이름 하나만 적는 목록이 아니라 패턴 규칙으로 읽히는 설정 파일이다.
