# 기본 명령어

> 중요도: ⭐⭐⭐ — 익숙하지 않아도 된다. 자주 보는 몇 가지만 받아들이면 충분하다.

## 먼저

이 가이드에서는 사용자가 Git 명령어를 전부 외우는 것을 목표로 하지 않는다.

실제로는 AI 에이전트에게 많이 맡기게 된다. 다만 아래 명령어들이 무슨 역할인지 정도는 알아두면 훨씬 덜 불안하다.

## 에이전트와 함께 쓸 때

실제로는 이렇게 맡기면 된다.

- "변경 내용 확인하고 커밋해줘"

사용자는 모든 명령어를 외우기보다, 지금 무엇을 하고 있는지만 알면 된다.

## 실제 흐름은 이 정도면 된다

```text
1. 작업 시작 전에 git pull
2. 작업이 한 덩어리 끝나면 git add .
3. git commit -m "메시지"
4. 바로 git push
```

즉, `pull -> 작업 -> add -> commit -> push` 흐름만 익숙해지면 된다.

## 이것만 기억하면 된다

- `pull` - 시작 전에 최신 내용 가져오기
- `commit` - 여기까지 저장하기
- `push` - GitHub에 바로 백업하기

`add`는 커밋 전에 필요한 중간 단계라고만 알고 있으면 충분하다.

## 필요할 때 찾아보는 명령어

### `git pull`

GitHub에 있는 최신 내용을 가져온다.

```bash
git pull
```

작업 시작 전에 한 번 보면 된다.

### `git add .`

이번 저장에 넣을 변경을 모은다.

```bash
git add .
```

보통 에이전트가 처리해도 되고, 직접 할 때는 이 한 줄이면 충분하다.

### `git commit -m "..."`

여기까지의 작업을 하나의 저장 시점으로 남긴다.

```bash
git commit -m "서론 초안 작성"
```

메시지는 길게 쓰지 않아도 된다. 무엇을 했는지만 보이면 충분하다.

### `git push`

방금 저장한 내용을 GitHub에 올린다.

```bash
git push
```

이 가이드에서는 **커밋했다면 바로 push** 하는 흐름을 추천한다.
