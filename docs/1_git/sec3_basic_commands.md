# 기본 명령어

> 중요도: ⭐⭐⭐

처음부터 Git 명령어를 다 외울 필요는 없다. 여기서는 실제로 자주 보는 흐름만 아주 가볍게 본다.

## 한 줄 요약

**처음에는 `pull -> add -> commit -> push` 흐름만 알아도 충분하다.**

## 어떻게 생각하면 되나?

Git 명령어는 많아 보이지만, 초급 단계에서는 "최신 내용 가져오기 -> 저장할 내용 묶기 -> 기록 남기기 -> GitHub에 올리기" 흐름만 알면 된다.

명령어 하나하나를 외우기보다 지금 내가 어느 단계에 있는지만 이해하면 된다.

## 그냥 이렇게 쓰면 된다

실제로는 이 정도 흐름이면 충분하다.

```text
1. 작업 시작 전에 git pull
2. 작업이 한 덩어리 끝나면 git add .
3. git commit -m "메시지"
4. 바로 git push
```

각 명령은 이렇게 생각하면 된다.

- `git pull`: 시작 전에 최신 내용 가져오기
- `git add .`: 이번 저장에 넣을 변경 모으기
- `git commit -m "..."`: 여기까지 저장하기
- `git push`: GitHub에 백업하기

실제로는 에이전트에게 이렇게 맡겨도 된다.

- "변경 내용 확인하고 커밋해줘"
- "커밋하고 바로 push 해줘"
- "지금 상태 보고 다음 Git 명령어 알려줘"

## 이것만 기억하면 된다

1. 처음에는 몇 개 명령만 알아도 된다
2. `commit`은 저장이고 `push`는 GitHub 백업이다
3. `add`는 커밋 전에 넣을 변경을 모으는 단계다
4. 헷갈리면 에이전트에게 맡겨도 된다

## 고급 과정

초급 단계에서는 흐름만 알아도 된다. 하지만 기본 명령어를 더 정확히 이해하면, 왜 순서가 중요한지와 어디서 문제가 생기는지가 보인다.

### 1. 왜 `pull`부터 하나?

`git pull`은 원격 저장소의 최신 내용을 가져와 내 로컬 작업과 맞추는 동작이다.

작업 전에 `pull`을 해두면:

- 다른 컴퓨터에서 작업한 내용과 어긋나는 일을 줄일 수 있고
- push할 때 충돌이 날 가능성을 줄일 수 있다

### 2. `add`는 왜 필요한가?

`git add`는 작업 폴더의 변경을 staging area로 올리는 명령이다.

즉, Git에게 "이번 커밋에는 이 변경을 넣을게"라고 알려주는 단계다.

`git add .`은 현재 폴더 아래의 변경을 넓게 담는 쉬운 방식이고, 더 익숙해지면 파일별로 선택해서 올릴 수도 있다.

### 3. `commit`은 정확히 무엇인가?

`git commit`은 staging area에 모아둔 상태를 하나의 기록으로 남기는 동작이다.

중요한 점은, 커밋은 단순 저장 버튼이 아니라 "의미 있는 변경 묶음"을 남기는 일이라는 점이다.

그래서 커밋을 잘 쪼개면 나중에:

- 기록을 읽기 쉽고
- 되돌리기 쉽고
- 비교하기 쉽다

### 4. `push`는 왜 따로 있나?

많은 초보자가 `commit`과 `push`를 같은 것으로 느낀다. 하지만 둘은 다르다.

- `commit`: 내 컴퓨터의 로컬 저장소에 기록 남기기
- `push`: 그 로컬 기록을 GitHub 같은 원격 저장소에 올리기

그래서 커밋했다고 해서 자동으로 GitHub에 올라가는 것은 아니다.

### 5. 자주 헷갈리는 상태

기본 명령어를 쓰다 보면 보통 세 상태를 오간다.

- 작업 폴더에서 파일을 수정한 상태
- staging에 올린 상태
- commit으로 기록된 상태

이 세 단계를 구분하면 Git이 훨씬 덜 헷갈린다.

### 6. 처음부터 다 외워야 하나?

그럴 필요는 없다. 다만 아래 정도는 이름과 역할이 연결되면 좋다.

- `status`: 지금 Git 상태 보기
- `diff`: 무엇이 바뀌었는지 비교하기
- `log`: 커밋 기록 보기
