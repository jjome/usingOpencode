# 기본 명령어

> 중요도: ⭐⭐⭐ — 매일 쓰는 핵심 명령어. 이것만 알면 Git의 80%를 쓸 수 있다.

## 전체 흐름

```
작업 → add (무대에 올리기) → commit (저장) → push (업로드)
                                              ↕
                                          pull (다운로드)
```

논문을 쓰고, 의미 있는 단위가 되면 add → commit. 하루 끝에 push로 백업.

## 저장소 만들기: `git init`

논문 폴더에서 Git을 시작한다.

```bash
git init
```

이 명령어를 치면 폴더 안에 `.git` 숨김 폴더가 생긴다. 이제 이 폴더는 Git 저장소다.

**한 번만 실행하면 된다.** 이미 저장소인 폴더에서 다시 칠 필요 없다.

## 상태 확인: `git status`

지금 뭐가 바뀌었는지 확인한다. 가장 자주 쓰는 명령어.

```bash
git status
```

```
Changes not staged for commit:
  modified:   서론.md          ← 수정했지만 아직 커밋 안 한 파일

Untracked files:
  본론.md                      ← 새로 만든 파일 (Git이 아직 모름)
```

**헷갈릴 때마다 `git status`부터 치자.** 현재 상태를 알려준다.

## 무대에 올리기: `git add`

커밋에 포함할 파일을 선택한다. "이 파일들을 저장하겠다"고 표시하는 것.

```bash
# 특정 파일만
git add 서론.md

# 여러 파일
git add 서론.md 본론.md

# 바뀐 파일 전부
git add .
```

> **비유**: 사진을 찍기 전에 누가 프레임에 들어올지 고르는 것. add는 "이 사람 들어와", commit은 "찰칵".

## 저장하기: `git commit`

add한 파일들을 하나의 세이브 포인트로 저장한다.

```bash
git commit -m "서론 초안 작성"
```

`-m` 뒤의 따옴표 안에 **뭘 했는지** 쓴다.

### 좋은 커밋 시점

| 좋은 시점 | 나쁜 시점 |
|---|---|
| 서론 초안 완성 | 한 문장 고침 |
| 2장 피드백 반영 | 하루치 작업 통째로 |
| 참고문헌 추가 | 3일간의 변경 한 번에 |

**의미 있는 단위**로 커밋하는 게 핵심이다. 너무 잘게 나누면 이력이 지저분하고, 너무 크면 되돌리기가 어렵다.

## 이력 보기: `git log`

지금까지의 커밋 기록을 본다.

```bash
git log --oneline
```

```
a1b2c3d 참고문헌 정리
f4e5d6c 2장 피드백 반영
7g8h9i0 서론 초안 작성
```

이 이력이 있으면 "2장 피드백 반영하기 전 상태로 돌아가고 싶다"가 가능해진다.

## 변경 내용 보기: `git diff`

마지막 커밋 이후 뭘 바꿨는지 확인한다.

```bash
git diff
```

```diff
- AI는 다양한 분야에서 활용되고 있다.
+ AI는 의료, 교육, 금융 등 다양한 분야에서 활용되고 있다.
```

`-`는 삭제된 줄, `+`는 추가된 줄. 커밋 전에 확인하면 실수를 잡을 수 있다.

## 업로드: `git push`

내 컴퓨터의 커밋을 GitHub에 올린다.

```bash
git push
```

**하루 작업이 끝나면 push 한 번.** 이게 백업이다.

## 다운로드: `git pull`

GitHub에서 최신 상태를 가져온다.

```bash
git pull
```

다른 컴퓨터에서 작업했거나, 지도교수가 직접 수정한 경우에 쓴다.

## 일상 루틴 요약

```
1. 논문 작업 시작
   └── git pull                 (최신 상태 가져오기)

2. 의미 있는 단위 작업 완료
   ├── git status               (뭐가 바뀌었나 확인)
   ├── git diff                 (변경 내용 확인)
   ├── git add .                (무대에 올리기)
   └── git commit -m "메시지"   (저장)

3. 하루 작업 종료
   └── git push                 (GitHub에 백업)
```

## 명령어 치트시트

| 명령어 | 역할 | 언제 쓰나 |
|---|---|---|
| `git init` | 저장소 생성 | 프로젝트 시작할 때 한 번 |
| `git status` | 현재 상태 확인 | 수시로 |
| `git add .` | 변경 파일 선택 | 커밋 전 |
| `git commit -m "..."` | 세이브 포인트 생성 | 의미 있는 작업 단위마다 |
| `git log --oneline` | 이력 확인 | 되돌리기 전, 상태 파악 |
| `git diff` | 변경 내용 비교 | 커밋 전 확인 |
| `git push` | GitHub에 업로드 | 하루 끝, 중요 작업 후 |
| `git pull` | GitHub에서 다운로드 | 작업 시작 시 |
